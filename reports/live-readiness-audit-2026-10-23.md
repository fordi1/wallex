# ممیزی آمادگی لایو — ۱۴۰۵/۰۸/۰۱

## نتیجه

**NO-GO — اجرای لایو خودکار در وضعیت فعلی ایمن نیست.**

هیچ سفارش واقعی در این ممیزی ارسال نشد. رابط کاربری نیز در حالت لایو دکمهٔ
فعال‌سازی را به‌درستی قفل نگه داشت.

## شواهد اجرایی

| بررسی | نتیجه | جزئیات |

| Ruff | قبول | بدون خطا |
| pytest | قبول | ۶۶ تست؛ اجرا روی Python 3.14.6، نه نسخهٔ هدف 3.11 |

## موانع P0

1. **گیت‌های خارجی کامل نیستند.** `config.yaml` allowlist و زمان‌ها را
   «موقت/اعلام‌شده توسط تیم» معرفی می‌کند. فایل `.env` نیز شش فلگ لایو را
   `false` نگه داشته و Telegram تنظیم نشده است.
2. **گیت سایه رد شده است.** اولین/آخرین تصمیم shadow بین 19:30 و 22:00 UTC
   است (۲۶ تصمیم). این اجرای ۲۴ ساعتهٔ پیوسته نیست و آخرین فرایند نیز کرش کرده است.
3. **reconciliation خصوصی لایو خراب است.** پاسخ واقعی
   `/v1/account/trades` در `result.AccountLatestTrades` قرار دارد، اما adapter
   ظرف `trades` و فیلدهای `id` و `side` را انتظار دارد. حتی پاسخ خالی نیز
   `KeyError: id` ایجاد می‌کند.
4. **محدودیت canary می‌تواند در یک cycle شکسته شود.** همهٔ نمادها با snapshot
   یکسان `positions/cash/equity` ارزیابی می‌شوند؛ fill نماد اول پیش از ارزیابی
   نماد دوم وارد snapshot نمی‌شود.
5. **خروج trailing و time-stop در runtime عملاً غیرفعال است.** `bars_held` و
   `trailing_stop` برای position زنده به‌روزرسانی نمی‌شوند.
6. **stop نرم‌افزاری به MARKET تبدیل نمی‌شود.** همهٔ خروج‌های استراتژی با
   `use_market=False` ارسال می‌شوند، حتی stop/trailing اضطراری.
7. **race لغو/پرشدن می‌تواند موقعیت بدون حفاظت یا خرید اضافه بسازد.** نتیجهٔ
   نهایی cancel دوباره خوانده و اعمال نمی‌شود و retry با مقدار کامل ممکن است.
8. **SQLite برای live مجاز است و lock واقعی ندارد.** دو process محلی می‌توانند
   هم‌زمان leader شوند؛ تضمین single-replica فقط با PostgreSQL برقرار است.

## موانع P1

- reconciliation fillهای exchange را به position محلی اعمال نمی‌کند؛ stop-fill
  یا partial-exit می‌تواند drift دائمی بسازد.
- restart، peak equity، day-start equity، cooldownها و half-size state را از SQL
  بازیابی نمی‌کند.
- تصمیم خروج ثبت نمی‌شود و تصمیم ورود پس از submit نوشته می‌شود؛ crash می‌تواند
  سفارشی بدون decision record باقی بگذارد.
- fee-aware edge فقط maker را وارد می‌کند، در حالی که خروج اضطراری/پایانی taker است.
- قیمت limit خروج پایانی quantize نمی‌شود و مسیر مشخص ثبت dust زیر حداقل وجود ندارد.
- verifier فعلی فقط فاصلهٔ اولین و آخرین تصمیم را می‌سنجد و continuity، crash،
  restart recovery و گزارش نهایی را اثبات نمی‌کند.
- هشدارهای fill، rejected order، AI fallback، آستانه‌های ۳٪/۶٪ و milestones
  خروج پایانی کامل نیستند.

## UX

نقاط مثبت:

- دادهٔ قیمت، کندل و order book واقعی است و دادهٔ نمایشی استفاده نمی‌شود.
- نمودار TradingView-style، تغییر timeframe، EMA/حجم، watchlist، book، signal و
  وضعیت موتور در یک workspace روشن قرار دارند.
- در عرض‌های 320، 360، 390، 640 (تقریب 200٪ zoom)، 768 و 1280 پیکسل سرریز افقی
  دیده نشد؛ کنترل‌ها در موبایل wrap می‌شوند.
- تب لایو دلایل بسته بودن گیت‌ها را نشان می‌دهد و دکمهٔ فعال‌سازی disabled است.

موارد اصلاحی:

- دلایل گیت لایو انگلیسی‌اند و قرارداد فارسی-only را نقض می‌کنند.
- body متن 14px است؛ حداقل خوانایی design system برابر 16px است.
- رنگ‌ها و left/rightهای فیزیکی در `web/terminal.html` باید به semantic token و
  logical properties تبدیل شوند.
- نمودار canvas باید جدول OHLCV دسترس‌پذیر و keyboard fallback داشته باشد.
- زمان باقی‌ماندهٔ UI حدود ۲۱ ساعت نشان می‌دهد، ولی اپراتور ۱۴ ساعت اعلام کرده؛
  timestamp رسمی قبل از هر اجرا باید تصحیح شود.

## تصمیم عملیاتی پیشنهادی

1. live را برای این چالش روشن نکنید؛ با زمان باقی‌مانده، گیت ۲۴ ساعته دیگر
   قابل تکمیل نیست.
2. shadow را فقط پس از اصلاح crash/retry و verifier از نو آغاز کنید.
3. P0های lifecycle سفارش، position recovery، stop و multi-symbol exposure را
   با تست integration برطرف کنید.
4. تست‌ها را داخل image واقعی Python 3.11 اجرا و Docker build را با daemon روشن
   بازتولید کنید.
5. allowlist و زمان رسمی، PostgreSQL backup/restore، Telegram delivery، کلید
   trade-only/IP-restricted و reconciliation خواندنی موفق را به‌صورت artifact
   ثبت کنید؛ سپس یک canary تازه با محدودیت‌های فعلی اجرا شود.

## ارزیابی استراتژی

گزارش یک‌هفته‌ای BTCTMN با AI روشن بازده `-0.0045%` و یک معامله دارد؛ نسخهٔ
AI خاموش `+0.046%` با سه معامله ثبت کرده است. این نمونه برای نتیجه‌گیری آماری
یا توجیه ریسک لایو کافی نیست. نتیجهٔ مثبت هدف است، نه شاهد آمادگی عملیاتی.
